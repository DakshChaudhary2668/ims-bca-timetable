# Decisions

| Decision                                         | Rationale                                                                                                                                                                                                                                                                              |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Keep Next.js, one Express API and PostgreSQL     | One API owns authorization, validations, writes and transaction boundaries. The browser keeps the current timetable design and uses the same-origin proxy.                                                                                                                             |
| Keep Prisma and the pg adapter                   | The generated client provides typed access to the existing relational schema and transactions. Reviewed SQL migrations cover PostgreSQL-specific constraints, exclusions and triggers.                                                                                                 |
| Plan Supabase PostgreSQL                         | Managed PostgreSQL can host the same relational schema while reducing operational work. Direct database connectivity preserves the API boundary. Migration, extension, grant and TLS checks are required before adoption. Supabase Auth and Data API integration are outside the plan. |
| Version the entire academic year's teaching week | Faculty and room conflicts can cross semesters. One working revision makes stale edit detection simple.                                                                                                                                                                                |
| Keep the PL in control of publication            | The API revalidates in a transaction and preserves immutable history. Python only returns a proposed draft.                                                                                                                                                                            |
| Keep substitutions in Node.js                    | Dated approvals must share faculty, version and transaction checks with the existing API. A second substitution service would split those responsibilities.                                                                                                                            |
| Preserve historical labels and placements        | Published versions store a display snapshot. A new draft uses current catalog labels and copied placement references.                                                                                                                                                                  |
| Bind both apps to loopback today                 | The current bearer-key configuration and public reads need explicit deployment and visibility decisions before shared access.                                                                                                                                                          |

## Open decisions

The PL must confirm substitution-inclusive workload, eligibility, batch and shared-session rules, room/lab suitability, calendar details, break semantics and availability defaults. The total including substitutions remains unset. Daksh must confirm approved hosting, account lifecycle and visibility rules before exposing institutional data.
